- 2026-05-17 — L18: "How does this break?" — `#failure-mode` — Module 6 opened. Framed AI default = optimism (happy-path generation dominates training data); the human's job is the inverted lens. The discipline shift: from **vibes-based pessimism** (squinting at code and feeling vaguely worried — not a skill) to **systematic pessimism** (a fixed 8-dimension rubric walked in order every time, until it becomes muscle memory). Rubric committed: (1) bad input — empty, very long, whitespace, wrong type, special chars; (2) state boundaries — null/undefined where unexpected, stale state, off-by-one; (3) mobile/cross-device — 320px iPhone SE, iPad, 4K, touch vs mouse vs keyboard; (4) browser/runtime compat — old Safari, Firefox/Linux, print stylesheets, strict tracking blocked; (5) SSR vs client / hydration — server-vs-client render mismatch, null-on-first-paint flicker; (6) scale/network — 0 results, 1 result, 10000 results, slow network, no network, race conditions; (7) accessibility (audience-calibrated per L17 sidebar) — keyboard, motion sensitivity, sun glare, color blindness; (8) future-edit fragility — does the next person editing this break the invariant silently? Applied to Bucket 1 changes shipped right before this lesson (focus-visible outlines, motion-safe variant, usePathname active state, Escape handler, p-2.5 touch target, ctaHref guard, CTA constants). Walked each change through all 8 dimensions; most returned "doesn't apply" (a *successful* walk, not a failure — rubric is a checklist of questions, not a list of fixes). Findings sorted by severity into ship-as-is / fix-now / defer. **Highest-severity concern**: `usePathname()` in Navbar.tsx can return null during the SSR/hydration window (Next.js App Router Client Component hook behavior), AND exact-equality `pathname === href` fails on trailing-slash mismatch (e.g., pathname returns `/about/` while link is `/about`). Both are real production gotchas. **Fix applied**: replaced `const isActive = (href) => pathname === href` with a normalize helper (`path.replace(/\/+$/, "") || "/"`) and an explicit null guard (`pathname !== null && normalize(pathname) === normalize(href)`). Verified typecheck. The regex strips one or more trailing slashes, the `|| "/"` keeps the root path as `"/"` after stripping, the null guard handles the SSR pre-hydration window. Other findings DEFERRED: Hero `ctaHref` doesn't catch whitespace-only `"   "` (no untrusted input currently, no action); Navbar Escape handler could collide with future modal handlers (no current collision, flag for CLAUDE.md when modals reappear on shared layouts); module-level CTA constants will drift if a Footer also references `/contact` (worth promoting to lib/constants.ts when second consumer appears); p-2.5 touch target meets WCAG 2.5.5 AAA exactly (44×44) but tight (some guidelines say 48). Bonus concepts: **rubric > worry** as the operational shift — most "code reviewer instinct" is unconscious rubric application; making it explicit lets you teach it and lets future-Claude apply it consistently; **the verdict is the value** — for each rubric finding the answer is ship-as-is / fix-now / defer-with-note, and deferring is a legitimate engineering choice (audience-calibrated, like the L17 Bucket sidebar); **canonical Next.js Client Component hook gotcha** — `usePathname`, `useSearchParams`, etc. can return null during SSR/hydration window; handle the null case if the result is observable in the UI; **normalization helpers** for URL/string comparison are tiny defensive primitives that prevent a class of contributor-variance bugs; **future-edit fragility** as a real rubric dimension — code that works today but invites the next person to break the invariant silently (most "code smells" are this dimension in different clothes).
